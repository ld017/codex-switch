# 定时预热实施计划（复核后）

状态：代码实现及自动测试完成；本机真实验收、安装结果另记。基线提交：`8d72e27905b14f6a0ab2d44c86603c5fd9ca5c38`。

## 复核修正后的硬门槛

- 首版计划时区固定 `Asia/Shanghai`；目标重置日决定周一至周五，反推到前一日的预热不重新判断工作日。
- 发送批次由统一单调 `batchDeadline` 约束，建议总网络预算 180 秒；发送、退出、后置核验共享预算，不在最后一个账号完成后重新加时。
- 每个账号在租约成功后重新读取当前凭据并核对稳定身份及身份版本；不能使用准备阶段的旧认证快照直接发送。
- 发送前在 `control.lock` 内原子保存 `sending` 意图、执行键和计划快照，写入并 `fsync` 成功后才释放锁和发送 `turn/start`；此前 CLI 仅做隔离初始化、身份和额度查询。双击、重启、进程崩溃都不能绕过同一去重路径。
- 控制写入失败直接禁止模型请求；`sending` 崩溃恢复必须先变成 `unknown` 后只读核验，不得把“没有完成记录”当作“没有发送”。
- 发送状态不明时只能读额度并压缩为 `unknown` 终态，禁止自动重发；详细结果清理不得删除执行水位、去重键或未知终态摘要。
- 临时 CLI 必须确认其进程退出后才释放执行预算、租约和临时目录；owner 记录 PID、进程启动时间、运行标识和租约 token，禁止工具调用以避免产生工作子进程；异常目录不能仅按 PID 清理。
- 发送 CLI 在完成并取得首个原始额度样本后退出；约 +15/+65 秒的后置核验由全局单并发短会话完成。首末样本跨度需满足确认要求，来不及采足即 `unknown`。
- 发送阶段不使用准备阶段的 auth 快照：claim lease 后重新读当前 vault 并核对稳定账号身份；续期失败不私自使用 refresh token fallback。
- `sending` 控制状态和防重复水位不随历史结果清理；发送后无论结果是否确定都必须形成终态，避免 pending 无限增长。

## 实施顺序

1. `WarmupModels`、固定时区 `WarmupPlanner`、`WarmupStore` 控制文件和原子状态事务。
2. `WarmupRPC`：隔离最小 CODEX_HOME、身份确认、无工具 ephemeral thread、turn 完成事件、原始 quota 多池读取、有界消息队列和进程回收。
3. `CLIWorkCoordinator`：普通刷新与预热共享全局预算；发送最多四路，核验最多一路，取消/租约/generation 统一。
4. `WarmupRunner`：基线筛选、发送意图、请求完成、首样本、后置核验、固定 reset 判据和 unknown 恢复。
5. `WarmupWindowController` 和 `AccountManager` 菜单入口：唯一非模态窗口、草稿与已保存设置分离、立即预热与定时计划分离。
6. 维护器：只回收本工具目录，日志沿用现有轮转；结果按 30 天/200 批/4 MiB 任一上限清理，控制水位不清理。

## 实施中复核修正

- 提前准备阶段不把已有窗口判定为最终跳过，避免旧窗口在触发前刚好到期。真正发送前在同一 CLI 会话重新读 quota，同时再次检查双边时间容差及计划 revision。
- 准备只持有短查询通道，5秒间隔及等候触发不持有账号租约；发送 gate 起统一180秒单调预算，准备另有最多120秒预算且不能越过计划容差。
- 后置核验偏移在全部发送进程退出后调度，沿用同一截止点；是否确认按实际样本时间戳及跨度判断，不假设恰好落在某一秒。
- 稳定身份由访问令牌的工作区与邮箱归一化派生，避免增加 id_token 或轮换 refresh token 改变去重身份。
- 执行键时间归一到秒，避免 JSON 日期精度损失导致加载后找不到状态。
- UI 资源只在窗口显示时采样，严重内存压力阻止新批次/发送；异常非空临时目录保留待核查。
- 所有账号身份变更共用取消等待门槛；普通查询在预算及租约取得后重新加载凭据，避免长排队后使用旧 token。
- 两轮独立审查发现的时间复核、窗口过早判定、末态工具事件、同步写阻塞和进程退出等待问题均已纳入修正及回归测试。
