# macOS 刷新与资源架构（2.3.2）

## 目标

恢复额度读取，缩短结果的可见延迟，降低查询峰值与共享代理临时分配。保留账号隔离、provider切换、共享历史、缓存兼容和回滚。

## 模块与数据流

| 模块 | 职责 |
| --- | --- |
| AccountManager / AppDelegate | 展示缓存与逐账号进度；菜单展开时更新已有视图，Token详情展开时从缓存构建菜单项 |
| UsageProvider | 合并请求、当前账号优先、最多一个查询CLI、租约与generation校验 |
| CLIUsageFetcher / RPC | 临时只读CODEX_HOME；额度先发布，再按需补Token；协议兼容与进程清理 |
| ProfileStore / UsageSnapshot | 持久化最后成功值、Token读取时间与短脱敏错误；兼容旧JSON |
| SharedHistoryProxy | 线性分行、Data请求改写、逐chunk释放临时对象；保留输出背压 |

菜单/定时器/手动刷新 → 合并调度 → 单个临时CLI → 额度即时发布 → 按需补Token → 缓存与进度发布 → CLI退出。

保留现有模块，避免每个账号常驻CLI增加长期内存，也避免自行维护非公开HTTP接口的认证与兼容。

## 策略

- 自动额度刷新5分钟；打开菜单时距最近尝试不足60秒，不重复启动。
- 完整Token结果15分钟内复用；冷启动或手动强刷重新获取。服务端日记录本身可能延迟。
- 额度不等待Token，也不等待其他账号；Token失败保留有效额度和旧统计，详情展示原因。
- 刷新中的强刷最多合并成一轮后续刷新；取消清空排队。新轮等待旧查询退出后再启动，旧generation不能回写。
- 重置卡仅返回数量、明细缺省或null时，保留数量，到期时间为未知；不推断为零张。
- 部分Token字段缺失时保留有效新字段，仅补旧字段；使用缓存时保留保守读取时间。
- 服务状态轮询60秒且防重入；打开菜单及操作后仍立即探测。
- 代理不硬截断合法大JSON；Foundation仍解析完整单条请求，超大单行仍需足够内存。

## 实施顺序

1. 用回归复现null/缺省重置卡解码失败，再修复可选明细与分阶段回调。
2. 覆盖单并发、强刷合并、取消、Token TTL与部分合并，再接入调度和菜单更新。
3. 建立相同输入基线，再优化代理扫描、Data转换与临时对象释放。
4. 执行完整测试、release构建、签名检查及本机只读验证；发布源码、安装包和SHA-256校验值。
