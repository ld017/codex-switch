# Codex Switch 菜单状态区精简设计

状态：设计与实施计划自检后，按用户要求交给新任务执行。本轮只写方案，不修改产品代码。

## 1. 目标、范围与成功条件

用户认为主菜单顶部五行灰色环境信息影响使用，要求先计划、重新设计展示框架、制定实施计划，再新开任务执行。

本次调整 macOS 菜单的信息层级、状态呈现和诊断刷新。主菜单首先服务看额度、切账号和定时预热；低频环境信息按需展开。正常及异常状态下，顶部环境状态区都恰好占一个标准菜单项，账号区域前移。

不重做账号卡、Token 汇总和预热面板，不修改连接策略、代理要求、凭据存储、服务恢复或共享历史实现。不涉及 Windows。

## 2. 当前事实与判断

现有 AppDelegate.rebuildMenu 在账号区前连续加入产品名、当前连接、Sub2API 服务、代理状态和共享配置五项，然后再加入两个提供方切换动作和共享刷新动作。

| 信息 | 源码实际证明的内容 | 新设计判断 |
| --- | --- | --- |
| Codex Switch 标题 | 产品名称，图标 tooltip 已有 | 删除独立标题行 |
| 当前连接 | 从配置读取的 provider | 保留一个紧凑入口，不标“联网正常” |
| Sub2API 在线/离线 | 127.0.0.1:8080 TCP 检查结果 | 进入诊断；仅当前 provider 为 Sub2API 时可影响入口提示 |
| 代理状态 | 特定 7897 端口、系统代理和 TUN 预检 | 进入诊断，不等同当前 OpenAI 已断线 |
| 代理变量冲突 | 命中已有全局代理变量风险规则 | 进入诊断；不宣称已经发生网络故障 |
| 共享任务/项目已配置 | 可执行代理及两处 CODEX_CLI_PATH 匹配 | 进入诊断，不宣称现有列表已经刷新 |

代理预检仍是现有“打开 Codex／切换连接／刷新共享视图”的前置门槛。本次移动展示位置不取消该门槛，失败仍通过已有操作提示说明。

## 3. 方案选择

- 全部删除：最省空间，但配置来源和排障入口不可见，不采用。
- 保留一行连接入口、展开看诊断：默认只占一行，仍能识别当前 provider，采用。
- 保留可折叠的五行说明区：需要自定义折叠状态且仍抢占主菜单，不采用。

采用原生 NSMenu 子菜单，不增加常驻诊断窗口、动画或持久化折叠设置。

## 4. 菜单信息层级

主菜单顺序：

1. **连接：OpenAI 官方 ▸**，或对应的当前状态文案。
2. 分隔线。
3. 现有 AccountManager.appendItems 的完整账号区：汇总、卡片、Token 明细、刷新额度、定时预热和账号管理，保留其内部顺序和功能。
4. 分隔线。
5. 原有“切换到 OpenAI 官方…”和“切换到 Sub2API…”两个直接动作，保留选中状态和禁用规则。
6. 原有“打开 Codex”“登录时自动启动”“退出菜单栏工具”。

连接子菜单包含：配置提供方、本机 Sub2API 端口、代理环境风险、代理预检、共享启动配置、诊断更新时间；分隔线后放原有“刷新共享任务/项目视图…”动作。共享刷新只在此处出现一次，沿用原 selector、确认和忙碌保护。

相比当前布局，五项环境说明压成一项，两个提供方动作移到账号区之后，共享刷新收进子菜单。原来的重复标题行和对应旧字段应真正删除，不能只设隐藏却继续维护两套展示。

## 5. 顶部单行规则

| 条件 | 精确标题 | 视觉语义 |
| --- | --- | --- |
| 尚未读配置 | 连接：读取中… | 中性 |
| 配置为 OpenAI | 连接：OpenAI 官方 | 中性 |
| 配置为 Sub2API，端口未检查、检查中或缓存过期 | 连接：Sub2API | 中性 |
| 配置为 Sub2API，60秒内端口检查通过 | 连接：Sub2API | 中性，不标 API 在线 |
| 配置为 Sub2API，60秒内端口检查未通过 | Sub2API · 端口检查未通过 | 注意 |
| 配置无法读取 | 连接：配置无法读取 | 注意，优先于其他诊断 |

中性图标用 `network`，注意图标用 `exclamationmark.triangle`。不增加红绿联网灯，不增加第二条常驻告警。入口始终能展开诊断，即使正在切换；子菜单内会修改状态的动作仍按原有规则禁用。

“系统代理未开启”、非当前通道的 Sub2API 检查失败、共享配置检查未通过，都不会单独增加主菜单行或把 OpenAI 标成离线。

## 6. 诊断文案边界

- 提供方使用“配置提供方”，只表达配置来源。
- Sub2API 使用“本机 Sub2API 端口：已响应／检查未通过”，不写“API 正常”。
- 代理环境使用“未发现已知冲突／发现 N 项已知风险”；不展示变量值或带认证的代理 URL。
- Clash `.ready` 写“代理预检：符合当前应用要求”；`.localPortUnavailable` 写“代理预检：预期端口检查未通过”；`.systemProxyDisabled` 写“代理预检：系统代理未匹配预期”；`.tunDisabled` 写“代理预检：未检测到预期 TUN”。
- 共享使用“共享启动配置：已匹配／检查未通过”，不表示当前任务列表已刷新。
- 无结果先显示“未检查”；首次检查中显示“检查中…”。更新旧缓存时保留旧值，并通过更新时间行显示“正在更新…”。未知状态不能默认为成功或离线。

## 7. 展示与采样分离

展示层只消费一个有界快照，不发起进程或网络操作。快照只驻留内存，不新增数据库或配置文件。

- 主菜单打开时读取 provider；若当前为 Sub2API，再按60秒缓存请求本机端口检查。
- 展开连接子菜单时，按60秒缓存请求完整诊断。
- 保留既有60秒状态计时器以降低回归范围，但菜单关闭时只刷新轻量配置/按钮状态，不为了刷新这些显示项运行 nc、scutil、ifconfig、launchctl 等诊断子进程；启动和主动操作原有必需检查不受影响。菜单显示且当前为 Sub2API 时可复用端口检查缓存。
- 一个诊断控制器最多一个采样任务。进行中的简略采样遇到完整诊断需求时合并为至多一次后续完整采样；重复悬停不能堆积任务。
- 切换完成、provider 变化和 stop 会使旧结果失效。异步结果不能覆盖更新的 provider，也不能把切换前端口结果重新写成切换后的故障。取消外层任务不等于实际 source 工作退出；采样槽必须等旧工作退出后才能释放并启动合并请求，stop 丢弃后续需求。
- 缓存时间差小于0或大于等于60秒视为过期；过期端口失败不维持顶部告警，等待新结果。
- 用户主动操作的 preflight 始终沿用现有新检查，不拿展示缓存替代安全和恢复流程。

## 8. 组件职责

| 组件 | 职责 |
| --- | --- |
| ConnectionStatusPresentation | 快照类型与纯展示规则，决定单行标题、图标语义、详情文案 |
| ConnectionStatusController | 复用 CodexSystem 的读取方法，控制按需采样、60秒缓存、单任务与旧结果失效 |
| ConnectionMenuSection | 持有唯一父项和稳定详情项，只更新标题/图标；独立处理连接子菜单打开事件 |
| MainMenuBuilder | 只定义主菜单组装顺序，便于不读取真实凭据地验证布局 |
| AppDelegate | 调用组装器、连接现有动作和生命周期，不再拼五行状态字符串 |
| AccountManager / WarmupService | 维持既有账号和预热职责，不因本次界面调整重写 |

AppDelegate.menuWillOpen/menuDidClose 必须只处理主菜单；连接子菜单不能触发 accounts.menuWillOpen、整菜单重建或账号刷新。异步诊断回调只能更新稳定菜单项，不能 removeAllItems 后重建正在跟踪的菜单。

## 9. 验收

- 正常主菜单顶部环境区一项，账号区紧随其后；旧五行不再常驻。
- 当前连接有文字标识，两个提供方切换动作仍直接可用，选中和忙碌禁用规则正确。
- OpenAI + 备用 Sub2API 检查失败 + 代理未匹配，不产生当前连接离线告警。
- Sub2API 当前端口检查失败和配置不可读均在同一个入口表达，详情始终可展开。
- 子菜单悬停不会刷新账号、丢失 Token 子菜单或增加多个诊断任务；菜单关闭不继续执行周期性重诊断。
- 定时预热入口、状态、账号变更取消等待、退出等待和原有共享历史流程完整保留。
- 无新增预热模型请求；展示测试使用可控假源。构建、签名、隐私扫描及回滚安装按现有流程执行。
- 原任务的 CUA 对此应用仍存在连接故障。新任务可以重试正常入口，但若工具仍失败必须标注视觉验收未完成，不反复要求用户解锁或打开同一窗口。

## 10. 自检结论

已对照截图和源码核对状态含义，避免把端口响应、配置匹配写成真实联网成功；保留所有操作前检查。方案没有新增主菜单多行说明、设置项或后台常驻检查器。独立只读审查指出的子菜单 delegate、稳定菜单项及旧异步结果风险已纳入设计和实施测试。
