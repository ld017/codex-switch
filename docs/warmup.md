# 定时预热

在 Codex Switch 原菜单的“刷新账号额度”下方点击“定时预热…”，打开独立窗口。重复打开复用同一窗口，关闭窗口保留本次草稿；只有“保存计划”才改变定时设置。“立即预热”只执行当前选择，不会开启定时计划。

## 使用

1. 选择 1–4 个已保存的 ChatGPT OAuth 账号。不同卡片若实际为同一个账号，只处理一次。
2. 选择“预热时刻”或“目标重置时刻（预计）”。后者按目标时刻减去5小时反推发送时间；实际重置以服务器报告和核验为准。
3. 选择每天、周一至周五或仅一次。周一至周五按目标重置日判断；例如周一凌晨02:00的目标，对应周日晚21:00预热。
4. 打开启用开关并保存，或点击“立即预热”做一次手动执行。默认计划关闭。时区固定北京时间。
5. 在“执行结果”中看各账号状态。已存在的活动窗口会跳过，不能通过再发一句话将它移动到目标时刻。

保存计划后，窗口可以关闭；Codex Switch 本身必须保持运行，电脑需要唤醒、联网。退出应用即停止执行。睡眠错过的时点不会补发，超过计划时点30秒仍未能发出也会跳过。系统严重内存压力时不启动新的预热发送。

## 结果的含义

| 状态 | 含义 |
| --- | --- |
| 服务器窗口已确认 | 对应 turn 成功完成，至少3次同身份、同主额度池的读数跨越60秒且重置时刻固定，并与本次发送时间相符 |
| 已有窗口 | 最后一次发送前检查发现活动窗口，本轮未发送 |
| 未发送 | 凭据、身份、租约、时间或额度信息检查未通过，没有提交模型请求 |
| 未确认 | 已保存发送意图，但完成结果或固定重置证据不足；不会自动重发 |
| 已复查服务器报告 | 只读查到服务器当前报告；单个读数不证明窗口已经启动 |

空闲账号的服务器读数可能一直是“查询时间+5小时”，即使显示0%和一个未来时间，也不能当作启动成功。预热会消费一次最小模型请求的额度，指令短不等于总 token 开销只有几个字。

“复查结果”只查询，不补发请求。需要重新登录、移除或切换账号时，工具先取消预热并等待其 CLI 退出，再修改凭据。

## 内存、刷新和存储

- 窗口打开时，每2秒读取本工具自身及本功能所创建 CLI 的本机驻留内存；关闭窗口停止这项刷新，不发网络请求。已采样峰值只代表本次应用启动内已观察到的峰值。
- 等待计划和等待核验时没有预热 CLI。发送最多四个，发送全部退出后核验最多一个。普通刷新共享同一进程预算。
- 不设定时“清内存”，通过结束 CLI、释放有界消息队列和任务来回收。每路输出总量上限4 MiB，单条256 KiB，未处理队列最多128条；超限中止，不能丢掉关键事件后继续显示成功。
- 凭据沿用原有 vault。隔离 CLI 仅取得访问令牌，使用临时凭据模式和 ephemeral thread，不取得 refresh token，不复制用户配置、MCP、项目和真实聊天历史。
- 控制状态在 `~/.codex-switcher/warmup/control.json`，发送前原子保存并同步到磁盘。它保存计划、防重发水位和有限摘要，不随详细历史清理。
- 临时 CLI 文件在 `~/.codex-switcher/tmp/warmup/`，正常退出后立即清理。异常留下的目录只有在归属、过期、父进程已消失且目录仅剩 owner 标记时自动清理；含实际 CLI 文件的异常目录保留待检查。
- 详细结果达到30天、200批或4 MiB中任一上限即清理。日志沿用2 MiB加一份旧日志的轮转，旧日志超过14天清理。维护在启动和批次结束时执行，日志写入也执行轮转，不额外启动常驻清扫进程。
- CLI 无法确认退出时保留租约和临时目录，阻止后续查询和发送；这种异常需要检查残留进程及隔离记录，不能用清历史绕过。

服务器故障、账号限制、其他客户端使用及网络延迟都可能使某个账号无法在目标时刻启动。本工具能控制本地发送条件并报告实际结果，不能强制服务端同时重置四个账号。

## 开发验收

常规 `swift test` 不会发送真实请求。真实验收测试只有显式设置 `RUN_AUTHORIZED_WARMUP_LIVE=1` 才运行，并写入被忽略的 `artifacts/warmup-acceptance/`。必须先获得账号所有者对真实最小请求的授权；未知结果不得为了让测试变绿而重发。

DEBUG 构建的 `--warmup-ui-preview` 使用独立临时 home 和测试账号展示生产窗口，不读取真实账号；该分支不编入 release。
